# web effecter

브라우저에서 실행되는 8슬롯 기타 이펙터 실험실입니다. 정적 파일만 사용하므로 GitHub Pages에서 그대로 호스팅할 수 있습니다.

## 실행

로컬에서는 프로젝트 폴더에서 `python3 -m http.server 8000`을 실행하고 `http://localhost:8000`을 여세요. GitHub Pages에서는 이 파일들을 `hyoutenka/hyoutenka.github.io` 저장소의 게시 루트에 놓고 Pages를 활성화하면 `https://hyoutenka.github.io/`에서 실행됩니다. HTTPS 또는 localhost 환경이어야 오디오 입력과 AudioWorklet을 사용할 수 있습니다.

첫 화면은 **연습** 탭입니다. 영상 뷰어와 메트로놈을 함께 보며 연습할 수 있습니다. 상단의 **입출력** 버튼은 왼쪽 서랍을 열어 기타 입력, 출력 장치, 게인, 뮤트, 미터를 표시합니다. **이펙터 설정** 탭에서 8개 노드와 프리셋, 파라미터, 바이패스를 조절합니다. 탭이나 서랍을 열고 닫아도 오디오 엔진 및 재생 중인 영상·메트로놈 상태는 유지됩니다.

1. 상단의 **오디오 시작**을 누릅니다.
2. **입출력** 서랍에서 오디오 인터페이스의 기타 입력을 연결하거나 기타 DI 녹음 파일을 불러옵니다.
3. **이펙터 설정** 탭에서 8개 노드를 눌러 이펙트를 배치하고 파라미터와 바이패스를 조정합니다.
4. **연습** 탭으로 돌아와 영상을 틀고 메트로놈과 함께 연주합니다. 출력 장치 선택은 지원 브라우저에서만 동작합니다.

이펙트 노드를 다른 슬롯으로 드래그하면 두 슬롯의 위치를 교환합니다. 비어 있는 슬롯으로 옮길 수도 있습니다. 선택한 페달의 파라미터와 바이패스 설정이 함께 이동하며, 오디오 엔진이 실행 중이면 새 순서로 신호 경로를 다시 연결합니다. 터치 화면이나 키보드에서는 페달 편집기의 ←/→ 버튼으로 이웃 슬롯과 위치를 바꿀 수 있습니다.
드래그 중에는 들어 올린 노드가 포인터를 따라오며, 놓을 슬롯이 강조됩니다. 교환할 때 두 노드가 새 자리로 이동하고 체인 패널에 짧은 연결 효과가 나타납니다. 운영체제의 움직임 줄이기 설정을 켜면 이 효과를 생략합니다.

## 영상과 함께 연습

**연습실**의 영상 뷰어에 일반 유튜브·Shorts 링크를 넣어 불러온 뒤 플레이어에서 재생할 수 있습니다. 다른 사이트의 주소는 서버가 직접 동영상 데이터를 제공하는 HTTPS 주소라면 브라우저의 영상 플레이어로 재생을 시도합니다. 웹페이지 주소 자체, 임베드를 금지한 영상, 지원하지 않는 파일 코덱은 재생할 수 없습니다. **내 영상 파일**에서는 컴퓨터의 영상 파일을 선택할 수 있으며 영상은 업로드하지 않고 브라우저에서 로컬로 재생합니다. 링크나 파일을 바꾸면 기존 영상은 정지합니다.

메트로놈은 40~240 BPM, 2·3·4·6박, 클릭 음량, 탭 템포를 지원합니다. 첫 박은 더 높은 소리로 들립니다. **시작**을 누르면 오디오 엔진을 켜고 현재 선택한 기타 출력 장치로 클릭을 보냅니다. 입출력 뮤트 버튼은 기타와 메트로놈 클릭을 함께 음소거합니다. 영상 소리는 브라우저의 기본 출력 장치에서 독립적으로 재생됩니다. 두 소리를 같은 헤드폰으로 들으려면 브라우저 기본 출력과 앱의 기타 출력 장치를 일치시키세요. 영상과 메트로놈은 자동으로 박자 동기화하지 않으므로 재생에 맞춰 메트로놈을 시작하거나 템포를 조정하세요.

입출력의 **뮤트 OFF/ON** 버튼은 오디오 체인을 유지한 채 최종 출력만 즉시 음소거합니다. **입력 게인**은 기본 +6 dB에서 -12~+30 dB, **출력 레벨**은 기본 100%에서 0~200%로 조절할 수 있습니다. 출력 앞에는 -3 dB 임계값의 빠른 컴프레서로 과도한 피크를 억제합니다. IN/OUT 미터는 RMS dBFS를 표시하고 순간 피크가 디지털 최대치에 접근하면 붉게 표시합니다. 입력 게인을 올릴 때 0 dBFS에 닿지 않도록 조절하세요. 출력 레벨을 올려도 기타 인터페이스의 하드웨어 입력 레벨이 너무 작거나 다른 출력 장치·믹서 경로로 보내지는 경우는 별도 확인이 필요합니다. 입출력 미터 아래에는 브라우저가 제공하는 입력·엔진·출력 지연 추정치를 표시합니다. 이 값에는 인터페이스 드라이버나 외부 믹서·모니터링 경로의 모든 지연이 포함되지는 않으므로 실제 연주 왕복 지연과 같다고 볼 수 없습니다. 라이브 입력은 브라우저에 10ms 입력 지연을 *요청*하며, 브라우저나 장치가 이를 보장하지는 않습니다. 출력 장치 선택 시 지원 브라우저에서는 `AudioContext.setSinkId()`를 사용해 오디오 엔진에서 장치로 직접 보내고, 지원되지 않을 때만 미디어 스트림 경로를 사용합니다.

바이올린 음색을 시험하려면 노드에서 **Compressor → SAW Synth → IR → EQ → Chorus → Reverb**를 직접 배치하세요. SAW Synth는 단음 입력의 기본 주파수를 추적해 SAW를 합성하며, **Attack**으로 소리가 시작되는 속도를 조절합니다. SAW와 IR을 함께 배치하면 실제 바이올린 계열의 몸통 공명을 측정한 **Violin Octet · Treble (Gras 스테레오)** IR이 자동 선택됩니다. IR 블록에서 캐비닛·다른 악기 IR이나 사용자 WAV로 바꿀 수 있습니다. V 키 또는 VIOLIN 버튼으로 SAW와 IR을 함께 켜고 끕니다. 이 IR은 바이올린의 공명 특성만 적용하며 활 마찰음이나 연주 표현까지 만들지는 않습니다. 화음·잡음·급격한 음 전환에서는 피치 인식이 불안정할 수 있습니다. 오디오 파일과 IR은 브라우저 안에서만 처리하며 업로드하지 않습니다.

바이올린 IR은 [Alex Harker의 OctetViolins](https://github.com/AlexHarker/OctetViolins)의 Gras 스테레오 응답(Treble·Soprano·Alto·Bass)을 사이트에 포함합니다. 실제 Violin Octet 악기의 공명을 사용한 연구용 플러그인의 자료이며 [BSD 3-Clause 라이선스](irs/LICENSE-OctetViolins.txt)를 함께 표시합니다. 또 [Conner의 IR-Library](https://github.com/itsmusician/IR-Library)의 Violin Body Resonant 응답을 포함하며 [MIT 라이선스](irs/LICENSE-IR-Library.txt)를 보관합니다. 전자바이올린 전용 IR이라고 부르지 않습니다. 기타 DI의 SAW 변환에 바이올린 바디의 선형 공명을 더하는 실험이며 활의 마찰이나 연주법을 재현하지는 않습니다. IR 파일을 불러오지 못하면 블록은 드라이 신호를 통과시키고 오류를 표시합니다.

각 슬롯의 이펙트 선택 화면은 **Compressor / Drive / Delay / Reverb / Mod / SAW / Synth / Amp / IR / EQ** 대분류로 나뉩니다. Drive 안에는 오버드라이브·디스토션·퍼즈를 구분합니다. 녹색은 지금 선택할 수 있는 오디오 모델, 금색은 앞으로 추가할 후보입니다. [회로 및 DSP 자료 카탈로그](docs/pedal-circuit-catalog.md)에 나오는 모델 가운데 61개를 회로의 일반적인 토폴로지 또는 공식 기능을 참고한 **독립 DSP 근사**로 추가했습니다. A3 Stompbox Angel은 제조사의 JCM800 계열 음색 설명과 네 조작부(Volume·Gain·Bass·Treble)를 토대로 다단 소프트 클리핑과 독립 저역·고역 EQ로 구현했습니다. 공개된 부품별 회로를 확인하지 못했으므로 페달 실측 캡처나 회로 복제 모델로 표기하지 않습니다. 이 중 디지털 페달의 제조사 펌웨어와 모든 모드/파라미터를 복제한 것은 아니며, DD-200/500은 여섯 종류의 대표적인 딜레이 계열을 제공합니다. Web Audio 기본 블록과 `catalog-pitch-worklet.js`의 독립적인 피치 변환을 사용하며 피치 모델에는 약 30–85 ms 처리 창에 따른 지연이 있습니다. 기존 Jan Ray·OCD·CP10 모델과 SAW/Synth/Amp/IR도 계속 선택할 수 있습니다.

A3 Stompbox **Awesome**과 **Groovim(원형 Distortion)**을 독립 근사 모델로 추가했습니다. Awesome은 부스트/프리앰프부터 자연스러운 오버드라이브까지의 성격을 클린·소프트 클리핑 혼합으로, Groovim은 RAT 재해석 설명을 참고해 게인 뒤 하드 클리핑과 역방향 Filter로 구성했습니다. **Groovim 808** 캡처는 다른 제품이므로 사용하지 않았습니다. 두 페달의 공개 부품별 회로와 실측 DI/wet 짝은 확인되지 않아 내부 부품이나 원음을 복제했다고 주장하지 않습니다. **Groovim → Angel → Awesome** 순으로 세 노드를 놓고 개별 바이패스·순서 변경·슬롯 출력 레벨을 비교할 수 있습니다. 이 순서는 참고 시연의 페달 조합이며 임선호 기타리스트 본인의 모든 보드에서 고정된 신호 순서로 확인된 것은 아닙니다.

2026-10-03 단독 시연 기준으로 세 모델을 먼저 조정했습니다. Groovim은 어택이 너무 일찍 클리핑되지 않도록 게인을 낮추고 저중역을 보강했으며, Angel은 두 증폭단의 과도한 포화를 완화했습니다. Awesome은 제작사 단독 리뷰에서 설명한 Klon 성향의 부스트·크런치와 고음역의 정돈된 저역을 참고해 게인 연동 저역 차단을 추가했습니다. [단독 시연 목록과 판정 기준](docs/pedal-circuit-catalog.md#a3-단독-시연-기준-및-현재-판정)을 기록했습니다. **오디오 A/B를 통한 8/10 이상 판정은 아직 없으며 스택은 추가 보정하지 않았습니다.**

나머지 카탈로그 61개도 그래프·노브 동작을 점검하고, [공식 조작 자료와 단독 시연에 근거한 수정 및 미검증 목록](docs/pedal-circuit-catalog.md#2026-10-03-나머지-출시-모델의-단독-근사-점검)을 남겼습니다. OD-1/SD-1, RAT 계열의 Filter, 컴프레서 반응, Dimension C의 두 변조 탭, Pitch Fork 방향, DD Dual 지연선, Holy Grail Flerb 경로 등을 수정했습니다. 이들은 제품 음색을 정확히 측정해 복제한 모델이 아니며 같은 DI의 페달 전후 녹음과 노브 위치가 없어 유사도 점수를 매기지 않았습니다. 카탈로그 회귀 검사는 `npm test`로 실행합니다.

드라이브 스택은 예를 들어 **TS Mini → Angel → Amp → IR**처럼 왼쪽부터 직렬로 구성합니다. 각 슬롯 아래 dBFS는 그 슬롯의 **출력 RMS 레벨**이며, 다음 페달에 들어가는 신호의 크기를 확인할 수 있습니다. 순간 피크가 0 dBFS 부근이면 빨간색으로 표시합니다. 출력 마스터의 리미터는 맨 뒤에 있으므로 그 앞에서 드라이브가 과하게 눌리면 마스터 볼륨만 낮춰도 질감은 복구되지 않습니다. 앞 페달의 Level/Volume, Angel의 Volume과 전체 입력 게인을 함께 조절하세요.

Angel을 시연 음원에 맞춰 보정하려면 **같은 기타 DI 원본**과 그 DI를 **Angel만 통과시킨 결과**를 확보하고 노브 위치·샘플레이트·입출력 게인을 기록해야 합니다. 낮은/높은 피킹과 Gain 설정을 여러 개 담으면 레벨, 주파수 응답, 비선형 배음과 어택을 비교할 수 있습니다. 유튜브의 앰프·캐비닛·마이크·믹싱을 거친 단일 트랙만으로는 Angel만의 전달 특성을 분리할 수 없습니다. 현재 Angel은 이런 짝지은 실측으로 보정되지 않았습니다.

Amp에는 기존 기본 Amp 외에 **AC10 / Deluxe Reverb / JCM Capture**가 있습니다. 이 세 모델은 [TONE3000의 NAM WebAssembly 예제 저장소](https://github.com/tone-3000/neural-amp-modeler-wasm)에 공개된 `.nam` 파일을 해당 저장소의 고정 커밋에서 브라우저로 불러옵니다. 이 저장소의 `deluxe.nam`은 **Fender Deluxe Reverb**로 표기된 모델이며 Tweed 5E3 앰프 캡처는 아닙니다. 브라우저용 NAM 런타임 `neural-amp-modeler-wasm@2.0.1`은 버전이 고정된 jsDelivr 자산에서 가져오며, 서버 측에서 오디오를 처리하지 않습니다. 모델 자체의 캡처 설정은 고정되어 있고 Input trim은 실제 앰프 Gain 노브와 다릅니다. 기본 Output은 캐비닛 IR에서 줄어드는 레벨을 고려해 +6 dB로 설정했습니다.

프리셋 목록은 다음 세 앰프와 캐비닛 조합만 제공합니다. 각 프리셋은 **1번 앰프 → 2번 IR**이며 나머지 여섯 슬롯은 비어 있습니다. 페달과 바이올린용 체인은 노드 선택으로 직접 만들 수 있습니다.

| 프리셋 | 자동 선택되는 IR |
| --- | --- |
| AC10 | Vox AC30 2×12 · SM57 중간 거리 |
| Deluxe Reverb | Fender Deluxe 1×12 · SM57 중간 거리 |
| JCM | Marshall 1960 4×12 · SM57 중간 거리 |

기타·베이스 캐비닛 21종은 [CabImpulse](https://github.com/DCisHurt/CabImpulse)의 내장 48 kHz 녹음 자료에서 SM57 중간 거리 응답을 캐비닛별 하나씩 추출했습니다. Vox AC30·Fender Deluxe·Marshall 1960을 포함해 Marshall 1936·1960AHW·1970, Line 6 Vetta, ENGL Pro, Randall RS412XLT100, Krank Krankenstein, Bogner Uberkab, Mesa Standard, Orange 4×12, Genz Benz G-Flex, Fender Super Reverb, Roland JC-120, Supro Thunderbolt, Ampeg SVT·Portaflex, Aguilar DB, Gallien-Krueger Neo를 제공합니다. 여러 마이크·위치·샘플레이트 변형은 중복으로 등록하지 않았습니다. 원저작자 Roger Chen의 [MIT 라이선스](irs/LICENSE-CabImpulse.txt)를 함께 보관합니다. 앰프 캡처와 캐비닛 IR은 각각 별도 출처이며, AC10의 캐비닛은 같은 Vox 계열의 AC30 2×12로 골랐습니다. 실제 캡처 당시 사용한 캐비닛과 동일하다고 보장하는 매칭은 아닙니다. IR 노드에서 다른 IR이나 사용자가 가진 WAV 파일로 교체할 수도 있습니다. 외부 NAM 자산을 불러오지 못할 때 NAM 블록은 원음을 통과시키고 오류를 표시합니다. 브라우저 오디오 엔진은 모델의 기본 샘플레이트에 맞춰 48 kHz로 엽니다.

전자바이올린용으로 명시된 [pe_mace의 CC0 IR](https://freesound.org/people/pe_mace/sounds/696523/)도 확인했지만 Freesound 계정 로그인이 필요한 원본 다운로드라 기본 선택기에 포함하지 않았습니다. 권한 있는 원본 WAV가 있으면 IR 파일 불러오기로 적용할 수 있습니다. 같은 악기의 IR은 모두 좋은 소리를 보장하지 않으며 입력 악기·픽업과 녹음 조건에 따라 결과가 달라집니다.

`Jan Ray circuit` 프리셋은 사용자가 제공한 **Vemuram Jan Ray V1.0 회로도**를 토대로 만든 별도의 드라이브 블록입니다. 47 nF 입력 커플링과 1 MΩ 바이어스 저항, LM4558 비반전 증폭기의 가변 피드백 저항과 서로 반대 방향의 1N4148 직렬 다이오드 쌍, 47 pF 피드백 커패시터, 10 kΩ Treble·1.2 kΩ·47 nF 필터, 후단 약 2배 증폭과 1 µF 출력 커플링을 근사합니다. Gain, Bass, Treble, 내부 Trim, Volume을 조절할 수 있습니다. Bass/Trim의 복잡한 주파수 의존 피드백망은 단순화한 저역 차단과 입력 저항으로 근사했으며, 전원회로와 부품 편차 및 실제 기타 픽업 임피던스까지 SPICE 수준으로 재현한 모델은 아닙니다. 브라우저 입력 레벨은 실물 회로의 전압으로 보정되지 않아 실제 페달과 같은 노브 위치에서 동일한 음색을 보장하지 않습니다.

`OCD circuit` 프리셋은 사용자가 제공한 **Fulltone OCD의 CircuitLab 공개 회로도**를 토대로 만든 별도의 블록입니다. 22 nF·470 kΩ 입력 커플링, TL082 첫 증폭단의 68 nF·2.2 kΩ 저역 귀환과 20 kΩ·1 MΩ Drive 피드백, 22 pF 보상, 10 kΩ 직렬 저항 뒤의 1N4148·2N7000 MOSFET 클리핑, 150 kΩ·39 kΩ 및 100 nF·220 pF 후단 증폭, 33 kΩ 출력 경로에 22 kΩ을 병렬로 붙이는 HP/LP 스위치, 47 nF·10 kΩ Tone 경로를 근사합니다. HP/LP는 High Peak/Low Peak라는 모드 이름이며 각각 하이패스/로우패스 필터라는 뜻이 아닙니다. 다이오드·MOSFET 전압 특성과 회로의 주파수 의존 응답은 실시간 오디오 처리를 위해 단순화했으며, 입력 레벨 및 실제 페달 버전에 따른 부품 차이는 보정되지 않았습니다.

`CP10 circuit` 프리셋은 사용자가 제공한 **Ibanez CP10 (MP-CP2001) 회로도**의 BA6110 VCA와 트랜지스터·다이오드 검출 경로, 타이밍 커패시터를 기반으로 만든 압축 모델입니다. Sustain(500 kΩ), Attack(100 kΩ), Level(100 kΩ) 조절부에 맞춰 감도와 압축량, 검출 속도, 출력량을 변경합니다. 검출부의 주파수 제한과 약 0.38초의 고정 릴리스는 실시간 DSP를 위한 근사이며, 개별 부품의 전압·전류나 실물 페달의 정확한 압축 곡선을 측정해 보정한 모델은 아닙니다.

입력 장치의 모니터링/루프백 설정과 브라우저 출력이 중복되면 피드백이 생길 수 있습니다. 처음에는 출력 볼륨을 낮추고 헤드폰을 사용하세요. 오디오 지연 시간은 브라우저, 인터페이스 드라이버, 출력 경로에 따라 달라집니다.

## 실시간 출력 지연 점검

입출력 서랍의 **원음 직결 테스트**는 같은 입력 게인·브라우저 오디오 엔진·출력 장치를 사용하면서 이펙터 체인만 건너뜁니다. 원음도 늦으면 인터페이스 드라이버/버퍼, 브라우저 입력, 출력 장치 경로를 확인하세요. 원음은 빠르고 체인만 늦으면 SAW Attack이나 Pitch Window와 체인 배치를 확인하세요. 출력 장치 선택이 `AudioContext.setSinkId()`를 지원하지 않는 브라우저에서는 별도 장치 출력을 미디어 스트림으로 우회해 지연이 늘 수 있으며, 화면에 **미디어 경유 출력**으로 표시합니다. 이때 시스템 기본 출력을 인터페이스로 바꿔 앱에서도 **시스템 기본 출력**을 선택하면 Web Audio의 직접 경로를 씁니다.

2026-10-03부터 새 SAW·Synth 노드의 기본 Attack을 각각 145→25ms, 100→20ms로 낮추고, 피치 추적 갱신을 약 21→11ms 간격으로 줄였습니다. Pitch Fork·Whammy·PS-6의 새 노드 기본 Window는 52→35ms입니다. 노브로 긴 어택/창을 다시 선택할 수 있으며, 이 설정들은 기존 페달의 고유한 음향 지연을 제거하지 않습니다. 브라우저가 표시하는 입력·엔진·출력 추정치는 실물 기타 어택부터 귀에 들리는 순간까지의 왕복 실측값이 아닙니다. 1초 가까이 늦다면 원음 직결 테스트의 비교 결과를 먼저 확인하세요.
